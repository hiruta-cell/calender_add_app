# カレンダー登録ツール（calender_add_app）

メールやメッセージの文章から日付・時刻を見つけ出し、Googleカレンダーの予定作成画面を開くデスクトップツールです。
文章の解析はすべてこの PC の中で行い、文章を外部のサービスへ送りません。

> **開発中です。** 文章の貼り付け、画面の範囲キャプチャ（OCR）、日時の抽出、Googleカレンダーへの登録、設定画面、デスクトップのアイコン、ログイン時の自動起動ができます。

## まず試す（デモの文面で約5分）

はじめての方は、この章の手順で試してください。使う文面と画像は、すべて架空のものです（[demo/](demo/) フォルダ）。

### 1. 起動する

**Node.js 22.12 以上**と **Git** が必要です（`node -v` と `git --version` で確認できます）。Windows・Mac のどちらでも動きます。
ターミナル（Windows は「コマンド プロンプト」か「PowerShell」）で、次の4行を順に実行します。

```bash
git clone https://github.com/hiruta-cell/calender_add_app.git
cd calender_add_app
npm ci
npm start
```

「カレンダー登録ツール」のウインドウが開けば成功です（初回は Electron 本体のダウンロードに1〜2分かかります）。

### 2. 日本語のメールを登録する（基本の流れ）

1. [demo/texts/1-mail-ja.txt](demo/texts/1-mail-ja.txt) を開き、文面をすべてコピーします。
2. アプリの左の欄に貼り付け、「日時を抽出」を押します。
3. 右に日時の候補が出ます。
   - 「10月22日(木) 14:00」と「10月29日(木)」（時刻なし）の2件です（文章の「〜15:30」のような終わりの時刻は読み取りません。終了は候補ごとに選びます）。
   - 文章の中の日時の部分は色付きで表示されます。
4. 右の欄の下の「予定の内容」を確認します。
   - 件名（【架空】秋の社内勉強会のご案内）・場所（本社3階 第一会議室）・Zoom の URL が自動で入っています。
   - URL の下には、サイト名（zoom.us）と、偽のサイト（フィッシング）への注意が出ます。
5. 2件ともチェックを付け、「選んだ 2 件をGoogleカレンダーで開く」を押します。
   - チェックを付けると、候補の下に「終了」の一覧が出ます。10/22 は「1時間後（15:00）」、時刻のない 10/29 は「終日」が選ばれています。10/22 は「1時間30分後（15:30）」に選び直してみてください。
6. ブラウザで Googleカレンダーの予定作成画面が2つ開きます。アプリのウインドウは自動で最小化されます。
   - 内容を確かめて「保存」を押すと登録されます。試すだけなら、保存せずに閉じて構いません。

### 3. ほかの文面も試す

| 文面 | 見どころ |
|---|---|
| [demo/texts/2-chat-ja.txt](demo/texts/2-chat-ja.txt)（チャット） | 「来週火曜の午後3時」「10/23 夜7時」のような言い回しも日時になります。終了は、初めは1時間後が選ばれています。見出しがないので件名は空です（手で入れます） |
| [demo/texts/3-mail-en.txt](demo/texts/3-mail-en.txt)（英語のメール） | 「Oct 28, 2026, 2:00–3:00 PM」→ 2026年10月28日 14:00（終了は一覧で選びます）。件名・場所・Google Meet の URL も入ります |

「来週」は試した日から数えるため、日付は試す日によって変わります。

### 4. 画像から読み取る（実験機能）

1. [demo/images/](demo/images/) の画像（例：[1-mail-ja.png](demo/images/1-mail-ja.png)、縦書きの [3-notice-vertical.png](demo/images/3-notice-vertical.png)）を、アプリのウインドウにドラッグ＆ドロップします。
   - 画像をコピーして、アプリに貼り付けても読み取れます（Ctrl+V、Mac は Cmd+V）。
2. 文字を読み取り、日時の候補が出ます。あとは「2. 日本語のメールを登録する」の 3 からと同じです。

画面に表示した文字を読み取ることもできます。画像を画面に表示し、**Ctrl+Shift+Y**（Mac は **Cmd+Shift+Y**）を押して、読み取る範囲をドラッグで囲みます。
Mac では初回に画面収録の許可が必要です（[Mac での画面取り込みの許可](#mac-での画面取り込みの許可)）。
写真や SNS の画像は読み間違えることがあります。読み取った文章は左の欄で直せます。

### 5. 終わるとき

ウインドウを閉じてもアプリは終了せず、タスクトレイ（Mac はメニューバー）に残ります。
終了するときは、トレイのカレンダーのアイコンのメニューから「終了」を選びます。
消すときは、`calender_add_app` フォルダを削除してください（デスクトップのアイコンや自動起動を設定した場合は、[デスクトップのアイコンと自動起動](#デスクトップのアイコンと自動起動)の「やめるとき」の手順で）。

文章の解析も画像の読み取りも PC の中だけで行い、外部には送りません。外部へ送るのは、「保存」を押したときに Google に届く予定の内容だけです（[プライバシーとセキュリティ](#プライバシーとセキュリティ)）。

## 必要なもの

- **Node.js 22.12 以上**（`node -v` で確認できます）
- Windows または Mac

## 起動手順

```bash
git clone https://github.com/hiruta-cell/calender_add_app.git
cd calender_add_app
npm ci
npm start
```

- `npm ci` は、リポジトリに記録されたバージョンどおりに部品をインストールします（`npm install` ではなく `npm ci` を使ってください）。
- 初回の `npm start` では、Electron 本体（約100MB）を GitHub からダウンロードします。ダウンロードしたファイルは、部品に同梱されたチェックサムで改ざんがないか確かめられます。
- Node.js のバージョンが古いと `npm ci` が止まります。その場合は Node.js を更新してください。

## デスクトップのアイコンと自動起動

2回目からは、`npm start` を使わずにデスクトップのアイコンから起動できます。

1. 上の手順で一度 `npm start` で起動します（画面のビルドもここで行われます）。
2. 確認ウインドウの右上の「設定」を押し、「デスクトップにアイコンを作る」を押します。
   - Windows：デスクトップに「カレンダー登録ツール」のショートカットができます。
   - Mac：デスクトップに「カレンダー登録ツール」（矢印の付いた別名）ができます。本体はプロジェクトの中の `launcher/` フォルダにあります。
3. ログインしたときに自動で起動したい場合は、設定画面で「ログイン時に自動で起動する」をオンにして「保存」を押します（既定はオフ）。自動で起動したときはウインドウを出さず、タスクトレイ（Mac はメニューバー）のアイコンとキーで使えます。

注意：

- `git pull` で新しい版にしたときは、一度 `npm start` で起動してからアイコンを使ってください（画面のビルドが必要なため）。
- プロジェクトのフォルダを移動・名前変更したときは、設定画面で「デスクトップにアイコンを作る」を押し直してください。自動起動をオンにしていた場合、設定画面ではオフと表示されるので、オンにして保存し直してください（Windows・Mac とも）。
- やめるときは、①設定画面で自動起動をオフにして保存 → ②デスクトップのアイコンを削除 → ③プロジェクトのフォルダを削除、の順にしてください（Mac の自動起動の登録は `~/Library/LaunchAgents/local.calendar-add-app.plist`）。

## 設定

確認ウインドウの右上の「設定」で、次を変えられます。

| 項目 | 内容 |
|---|---|
| 予定の既定の長さ | 候補の「終了」で初めに選ばれている長さ（30・60・90・120分。既定は60分）。候補ごとに選び直せます |
| 範囲を選んで読み取るキー | Ctrl（Mac は Cmd）を含む組み合わせ＋英字・数字（既定は Ctrl+Shift+Y、Mac は Cmd+Shift+Y）。ほかのアプリが使っているキーは選べません。U はコピーした文章の読み取りに使うため選べません |
| コピーした文章を読み取るキー | 上と同じ組み合わせ＋U（既定は Ctrl+Shift+U、Mac は Cmd+Shift+U）。上の組み合わせ（Ctrl+Shift など）を変えると一緒に変わります |
| ログイン時に自動で起動する | オン／オフ（既定はオフ） |
| デスクトップにアイコンを作る | 上の「デスクトップのアイコンと自動起動」を参照 |

## 使い方

起動すると、確認ウインドウが開き、タスクトレイ（Mac はメニューバー）にカレンダーのアイコンが表示されます。
確認ウインドウを閉じてもアプリは終了せず、トレイに残ります（常駐）。終了するときは、トレイのアイコンのメニューから「終了」を選びます（Mac は Cmd+Q でも終了できます）。

### コピーした文章を読み取る（おすすめ）

メールなど、ほかのアプリの文章から登録するときの一番かんたんな方法です。

1. メールの本文など、日時が書かれた文章を選んでコピーします（**Ctrl+C**、Mac は **Cmd+C**。全部選ぶなら Ctrl+A／Cmd+A のあと）。
2. **Ctrl+Shift+U**（Mac は **Cmd+Shift+U**）を押します。トレイのメニューの「コピーした文章を読み取る」や、確認ウインドウの「コピーした文章を読み取る」ボタンでも同じです。
3. 確認ウインドウが前に出て、文章が左の欄に入り、日時の候補が表示されます。以降は、下の「文章を貼り付ける」の 3 からと同じです。

文字の読み取り（OCR）を使わないので、画面から読み取るより正確です。コピーした文章がないとき（画像だけをコピーしたときなど）は、コピーし直すよう案内します。

### 画面や画像から読み取る（実験機能）

文字の読み取り（OCR）は実験機能です。画面に表示されたきれいな文字はよく読めますが、SNS の背景付きの画像や写真は読み間違えることがあります。読み取った文章は必ず確かめ、違っていれば入力欄で直すか、日時を手入力してください。

画像は、確認ウインドウに**貼り付け（Ctrl+V、Mac は Cmd+V）**するか、**ドラッグ＆ドロップ**しても読み取れます（PNG・JPEG、20MB まで）。

### 画面から読み取る（範囲キャプチャ）

1. 読み取りたい画面を前面に出してから、**Ctrl+Shift+Y**（Mac は **Cmd+Shift+Y**。設定で変えられます）を押します。トレイのメニューの「範囲を選んで読み取る」や、確認ウインドウの「画面から読み取る」ボタンでも始められます。
2. 画面が暗くなるので、読み取りたい部分をドラッグで囲みます。やめるときは **Esc** キーか右クリックです。
3. 文字を読み取り（横書き・縦書きを自動で判定）、文章が左の欄に入って、日時の候補が表示されます。
   - 読み取った文章は、左の欄で直せます。直したら「日時を抽出」を押し直してください。
   - 縦書きと横書きを取り違えたときは、「横書きで読み直す」「縦書きで読み直す」を押します。
   - 15秒たっても読み取れないときは中断します。日時を手入力するか、範囲を小さくして選び直してください。
4. 以降は、下の「文章を貼り付ける」の 3 からと同じです。

### 文章を貼り付ける

1. 左の欄に、メールやメッセージの文章を貼り付けます。
2. 「日時を抽出」を押します（Ctrl+Enter、Mac は Command+Enter でも可）。
3. 右に日時の候補が表示されます。文章の中の日時部分は色付きで表示されます。
4. 登録したい候補にチェックを付けます。
   - チェックを付けた候補の下に「終了」の一覧が出ます。開始から「30分後」「1時間後」「1時間30分後」…「23時間30分後」（30分刻み）か「終日」を選びます。項目には終わる時刻も出ます（例：「1時間30分後（15:30）」、日をまたぐと「（翌日 01:00）」）。
   - 初めに選ばれているのは、時刻のある候補は設定の「予定の既定の長さ」（既定は1時間後）、時刻が書かれていない候補は「終日」です。時刻のある候補で「終日」を選ぶと、その日の終日の予定になります。
   - 時刻が書かれていない候補で長さを選ぶと、「開始」の欄が出ます。開始時刻を入れてください。
   - 文章に「14時〜15時」のように終わりの時刻が書かれていても、読み取るのは開始の時刻だけです（終了は一覧で選びます）。
5. 「予定の内容」を確認します。件名・場所・オンライン会議URL は、文章に「件名：」「場所：」「会場：」などの見出しや `https://` の URL があれば、自動で下書きされます。必要なら直してください。
   - 見出しがない場合も、先頭の方の「〇〇のお知らせ」「〇〇のご案内」のような行を件名に、「会場は〇〇です」のような文を場所に下書きします。
   - 場所の見出しも文もない場合は、「住所：」「所在地：」の行や、催しの一覧のページのように「宮城県塩竈市本町8-1 講習室」「塩竈市本町8-1 講習室」のように都道府県・市区町村から始まる行を場所に下書きします（県名がない場合は、番地が続く行か「登米市 / 芸術鑑賞」のような地域の行だけ。「宮城県登米市 / 芸術鑑賞」のような分類は除き、番地のある住所を優先します）。「架空市民会館」「架空国際センター 会議棟2F」のような施設名だけの行も場所にします（近くに住所があれば並べます）。メールの署名にある会社の住所は使いません。
   - オンライン会議URL は、場所が空なら「場所」に、場所があれば「メモ」の先頭に入ります。
   - URL があるときは、そのサイト名と「偽のサイトへ誘導するもの（フィッシング）の可能性があります」という注意が表示されます。送り主が信頼できるか、サイト名が正しいかを確かめてから登録してください。会議サービス（Zoom・Meet・Teams・Webex）以外のサイトには、強めの注意が出ます。
   - 件名は50文字までです（入力欄の下に残りの文字数が出ます）。長い件名の下書きは50文字で切ります。
   - 「元の文章をメモに入れる」は既定でオフです。オンにすると文章（先頭の500文字まで）が Google に送られます。
6. 「選んだ ◯ 件をGoogleカレンダーで開く」を押します。既定のブラウザで予定作成画面が開きます（複数選んだ場合は1件ずつ順に開きます）。
   - すべて開き終わると、ブラウザの操作の邪魔にならないよう、アプリのウインドウは自動で最小化されます。戻すときは、Dock（Mac）・タスクバー（Windows）のアイコンか、メニューバー（Mac）・タスクトレイ（Windows）のアイコンの「確認ウインドウを開く」を押します。
   - 途中でブラウザを開けなかった場合は最小化せず、エラーの内容を表示します。
7. ブラウザで内容を確認し、「保存」を押すと登録されます。保存すると、Googleカレンダーの画面に予定が表示されます。
   - アプリが登録の結果を自動で読み取ることはしません（Google のアカウントの情報を扱わないため）。
8. 登録してから60秒間アプリを操作しないと、次の登録に備えて、アプリの表示が自動でクリアされます。
   - その間にアプリを操作した場合（入力・クリック・貼り付け・読み取りなど）は、作業中の内容を消さないようクリアしません。

日時が見つからない場合は「日時の情報がありません」と表示されます。その画面で日付（と、必要なら開始時刻と終了）を入れて「追加する」を押すと、候補に加わります。日時を手入力で追加する欄は、候補の一覧の下にもあります。

## 対応している日付の書き方

| 書き方 | 例 |
|---|---|
| 月/日 時:分 | `10/15 14:00` |
| 月日(曜日) 時〜時 | `10月15日(木)14時〜15時`（読み取るのは開始の14時だけ） |
| 年月日 | `2026年10月15日` |
| 年→月→日の数字 | `2026/10/15`、`2026-10-15`、`2026.10.15`、`26.10.15`、`27/10/15`（年が2桁なら 20XX 年） |
| 漢字の数字 | `十月十五日`、`十五時三十分`、`二〇二六年十月十五日` |
| 明日 | `明日`、`明日の午後3時` |
| 来週◯曜 | `来週火曜`、`来週の火曜日 15:00〜16:00` |
| 英語 | `October 15, 2026`、`Oct 15`、`Oct. 15th`、`15 Oct 2026`、`10/15/2026`、`tomorrow` |

時刻は `14:00`、`14時`、`14時30分`、`14時半`、`午前10時`、`午後3時`、`3pm`、`3:00 PM`、`PM3:00`、`正午` の形に対応しています。
時間帯の言葉は、`朝`＝9時、`昼`＝11時、`夕方`＝15時、`夜`＝18時 を開始時刻にします（`夜7時` のように時刻が続く場合は19時。`朝17時` のように言葉と食い違う場合は、書かれている時刻を優先します）。
範囲は `14時〜15時`、`15:00-16:00`、`14時から15時`、`2:00–3:00 PM`、`2-3pm`、`from 2pm to 3pm` の形を1つの日時として読みます。終わりの時刻は使わず、開始の時刻だけを読み取ります（`2-3pm` は 14時開始）。終了は候補ごとに一覧から選びます。
日付と時刻が別の行に書かれたメール（`日付：10月22日(木)` の次の行が `時間：14時〜15時`、`Date:` の次の行が `Time:`）にも対応しています。全角の数字や漢字の数字（`十月十五日`、`十五時三十分`）も使えます。

日時の決め方：

- 年が書かれていない日付は、今日以降で最も近い日になります（例：10月11日に「10/5」→ 翌年の10/5）。
- 数字だけの日付は、年→月→日の順（日本式）として読みます（`26.10.15` は 2026年10月15日）。
- 年が最後の英語の日付は、`15/10/2026` のように日が13以上なら日/月（英国式）、それ以外は月/日（米国式）として読みます。`05/10/2026` のように月と日の順番が決まらないときは「月と日の順番を確認してください」と表示します。
- 「来週」は月曜始まりの週で数えます（例：日曜日に「来週火曜」→ 2日後の火曜日）。
- 終了は文章から読み取らず、候補ごとに「開始から30分〜23時間30分後（30分刻み）」か「終日」を選びます。初めは1時間後（設定で変えられます）、時刻が書かれていない候補は終日が選ばれています。
- 過去の日時には「過去の日時です」と表示されます。
- メールを貼り付けたとき、送信日・受信日（`Sent:`、`送信日時:`、`Date:`、`日付:` など）と、返信の引用の見出し（`On … wrote:`、`… さんは書きました:`、`… のメール:` など）の日付は予定にしません（Outlook・Thunderbird・Gmail・Apple Mail の書き方に対応）。件名の行の日付は予定として読みます。
- 日付の後ろに書かれた曜日が、その日付の本当の曜日と合わないとき（例：`2026年10月15日(水)`。本当は木曜日）は「書かれた曜日と日付が合いません。日付を確認してください」と表示します。日付は書かれたとおりに使い（候補には本当の曜日が表示されます）、件名・場所の下書きにある曜日も日付に合わせて直します（例：件名「10月13日(水)のご訪問」→「10月13日(火)のご訪問」）。登録は止めないので、どちらが正しいかを送り主に確かめてください。曜日が日付の前にある書き方（`Thursday, October 15`）は確かめません。
- 日時は日本時間（Asia/Tokyo）として扱います。日本国内での利用を前提にしています。

対応していない書き方：`10/15〜10/17`（複数日にまたがる範囲）、`今日`、`今週`、`再来週`、英語の `next Tuesday`（「今週」「来週」のどちらの意味か人によって違うため）など。

## Mac での画面取り込みの許可

Mac で初めて「画面から読み取る」を使うと、画面収録の許可を求められます。次の手順で許可してください。

1. 「システム設定」→「プライバシーとセキュリティ」→「画面収録とシステムオーディオ録音」を開きます。
2. 一覧の中から、アプリを起動したもの（ターミナルから `npm start` で起動した場合は「ターミナル」、VSCode のターミナルから起動した場合は「Visual Studio Code」）をオンにします。一覧にない場合は、一覧の下の「＋」から追加します（ターミナルは「アプリケーション」→「ユーティリティ」の中にあります）。
3. アプリを終了して、もう一度起動します（許可は起動し直したあとに有効になります）。

許可がないまま使うと、「画面を取り込む許可がありません」と表示されて取り込みを中止します。案内には、オンにするアプリの名前（起動に使ったアプリ。例：ターミナル、Visual Studio Code）が表示されます。案内の「システム設定を開く」ボタンを押すと、画面収録の設定画面が直接開きます。アプリが終了することはありません。

> 許可を求められる対象（アプリかターミナルか）は、起動のしかたによって変わります。デスクトップのアイコンや自動起動で起動したときに一覧に出る名前は、まだ確かめていません（未検証）。許可がないときの案内に表示される名前に従ってください。

## Windows での画面取り込み

特別な許可は要りません。

## プライバシーとセキュリティ

- 貼り付けた文章は、この PC の中だけで解析します。外部の AI や API には送りません。
- 文章をファイルに保存したり、ログに書き出したりしません。ファイルに保存するのは設定（予定の長さ・キー）だけです（アプリ用のフォルダの `settings.json`。本人だけが読める権限）。
- コピーした文章（クリップボード）を読むのは、ホットキー・トレイのメニュー・ボタンを押したときだけです。常に見張ったり、中身を書き換えたりしません。
- 画面から読み取るときに撮影した画像も、ファイルに保存しません。画面全体の画像は範囲を選んだ時点で消し、選んだ範囲の画像は確認ウインドウに表示している間だけメモリに置きます（「クリア」、確認ウインドウを閉じる、アプリの終了で消えます）。
- 登録してから60秒操作がなければ、表示していた文章と取り込んだ画像を自動で消します。
- 文字の読み取り（OCR）も PC の中で行います。読み取り用のデータはアプリと一緒にインストールされ、実行時にダウンロードしません。
- アプリの画面からは外部への通信ができない設定にしています。
- カレンダーに登録するときは、利用者が確認した件名・日時などが Google に送られます。予定作成画面の URL に内容が含まれるため、ブラウザの閲覧履歴にも残ります（会議 URL にパスコードが含まれる場合も同じです）。
- アプリがブラウザで開くのは、Googleカレンダーの予定作成画面だけです（Mac の「システム設定を開く」ボタンで開く画面収録の設定画面を除く）。それ以外の URL は開かない設定にしています。
- 脆弱性を見つけた場合は [SECURITY.md](SECURITY.md) の方法でお知らせください。

## 開発者向け

| コマンド | 内容 |
|---|---|
| `npm test` | 単体テスト（日時抽出・セキュリティ設定など） |
| `npm run test:smoke` | アプリを実際に起動し、画面を自動操作して確認する（約27秒。確認が30秒進まなければ止まったとみなして終了。ウインドウと範囲選択の画面が一瞬開きますが、選択はしないので、ほかのアプリでの文字入力は邪魔しません。設定は確認専用の一時フォルダに書き、終わったら消します。起動中のアプリはトレイのメニューから終了してから実行） |
| `npm run ocr:diagnose` | 文字の読み取り（OCR）の診断。デモの架空の画像を読み、PC の環境と結果を表示する（PC によって読み取りの結果が違うときの調査用。`-- --electron` を付けるとアプリと同じ Electron の中で動かす） |
| `npm run ocr:diagnose:canvas` | 文字の読み取りの診断（画面での画像の変換）。縦書きのデモ画像をアプリと同じ方法で変換し、変換の前後の違いと読み取りの結果を表示する |
| `npm run build` | 画面をビルドする |
| `npm run watch` | 画面のファイルを保存するたびにビルドする（別のターミナルで `npx electron .` を起動し、Ctrl+R / Command+R で再読み込み） |

読み取りテスト・デモ用の架空の文面の画像は [demo/images/](demo/images/) にあります（画面に表示して「画面から読み取る」で試せます）。
