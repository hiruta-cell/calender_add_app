## 1. 目的と概要

画面に開いている文章（メールやお知らせ）から日付・時刻を抜き出し、件名・場所・メモを下書きして、Google カレンダーの予定作成画面をブラウザで開くデスクトップツールです。

- 利用者：学習コミュニティのメンバー（約20人）
- 登録の仕組み：予定の内容を埋め込んだリンクを既定のブラウザで開きます。**利用者がブラウザで「保存」を押して、初めて登録されます。**
- 動作確認：Mac と Windows の両方で行います。
- 対象外（要件 §7）：Google Calendar API と OAuth による自動登録、指定したカレンダーへの自動登録、Windows 標準の OCR、インストーラーによる配布。

## 3. 基本の流れ

1. **取り込む**：文章を貼り付ける、コピーした文章を読み取る、画面の範囲を選ぶ、画像を貼り付ける・ドロップする（§4）。
2. **日時を抽出する**：PC の中のルール処理で、日付と時刻の候補を作る（§5）。外部には送らない。
3. **候補を選ぶ**：候補ごとにチェックを付ける。終了時刻を選ぶ（§7）。
4. **予定の内容を確かめる**：件名・場所・メモ・会議 URL の下書きを、利用者が直す（§6）。
5. **登録する**：「選んだ N 件を Google カレンダーで開く」。予定作成画面が件数分開く（§8）。
6. **保存する**：ブラウザで「保存」を押す（アプリの外の操作）。
7. **後始末**：予定作成画面をすべて開くと、ウインドウを最小化する。60秒操作がなければ、表示を初期状態に戻す（§12）。

## 4. 取り込みの方法

| 方法 | 操作 | 備考 |
|---|---|---|
| テキストの貼り付け（主機能） | 左の欄に Ctrl+V（Mac は Cmd+V） | 最も確実な方法 |
| コピーした文章の読み取り | ほかのアプリで文章をコピーし、**Ctrl+Shift+U**（Mac は Cmd+Shift+U）、トレイの「コピーした文章を読み取る」、ウインドウの同名のボタン | クリップボードを読むのは利用者の操作のときだけ。保存・記録・書き換えはしない |
| 範囲キャプチャ（追加機能） | **Ctrl+Shift+Y**（Mac は Cmd+Shift+Y）、またはトレイ・ボタン | 画面が暗くなり、ドラッグで範囲を選ぶ。Esc で中止。範囲が小さすぎると取り込まない |
| 画像の貼り付け・ドロップ | 画像を Ctrl+V、またはウインドウにドラッグ＆ドロップ | PNG・JPEG、20MB まで。長い辺が 3000 画素を超えるものは縮める |

- 範囲キャプチャのキーは、設定で変えられます（§9）。
- ホットキーは、利用者が操作したときだけ反応します。常時の録画・定期的な取得はしません。

### 4.1 画像の読み取り（OCR・実験機能）

- Tesseract.js を使い、横書き（`jpn`）と縦書き（`jpn_vert`）の両方で読み、確信度の高い方を採用します。横書きの確信度が 80 以上なら、縦書きの読み取りを省きます。
- 読み取りは合計 15 秒で中断します。中断したときは「日時を手入力するか、範囲を小さくして選び直してください」と案内します。
- 読み取りの結果が確信度 40 未満のときは、「精度が低い可能性がある」と知らせます。読み取った文章は入力欄で直せます。
- 文字データ（本体・日本語・縦書き）は npm の部品として同梱し、実行時に外部から取得しません。
- 精度の調整には凝りません（依頼者の方針）。OCR は「実験機能」として扱います（G6）。

## 5. 日時の抽出

### 5.1 対応する書き方

要件 §5.7 の5種類は、必ず対応します（単体テストで確かめています）。

| 書き方 | 例 |
|---|---|
| 月/日と時刻 | `10/15 14:00` |
| 日本語の月日・時刻 | `10月15日(木)14時〜15時`、`十月十五日`、`十五時三十分` |
| 年を含む日付 | `2026年10月15日`、`2026/10/15`、`2026-10-15`、`2026.10.15`、`26.10.15`（年が2桁なら 20XX 年） |
| 相対表現 | `明日`、`来週火曜`（基準は実行した日の「今日」） |
| 英語の日付 | `October 15, 2026`、`Oct 15`、`15 Oct 2026`、`10/15/2026`、`tomorrow` |
| 英語の時刻 | `3pm`、`3:00 PM`、`PM3:00`、`a.m.`/`p.m.`、`at 3pm`、`2-3pm`、`from 2pm to 3pm`、`正午` |
| 時間帯の言葉 | 朝＝9時、昼＝11時、夕方＝15時、夜＝18時。後ろに時刻があれば、その時刻を優先（例：夜7時→19時） |

### 5.2 読み方の規則

- **年が無い日付**：今日以降で最も近い日を採用します。過去の日付になるときは、候補に警告を出します（要件 §12）。
- **「来週」**：週は月曜始まり。今日の次の週を指します（要件 §12）。
- **数字だけの日付の順番**（`05/10/2026` など）：日が13以上なら日/月、それ以外は月/日として読みます。順番が決まらないときは「月と日の順番を確認してください」と表示します。
- **曜日の食い違い**：日付の後ろの曜日（`(水)`、`水曜日`、`(Wed)` など）が合わないときは、「書かれた曜日と日付が合いません。日付を確認してください」と表示します。日付は書かれたとおりに使い、直しません。登録は止めません。
- **メールの送信日・受信日は候補にしない**：`Sent:`、`Received:`、`送信日時:`、`受信日時:`、`Date:`（ヘッダーの中）、返信の引用の見出し（`On … wrote:` など）の日付を除きます。
- **日付と時刻が別の行**：日付が行末にあり、次の行が「時間：」「時刻：」「開始：」「Time:」「Start:」で始まるときは、その行の時刻を結び付けます。見出しのない行の時刻は結び付けません。
- **範囲の書き方**（`14時〜15時`、`2-3pm`）：範囲として読み、**開始の時刻だけを使います**。終了時刻は、利用者が選びます（§7）。
- **同じ開始で終了だけ違う書き方**は、1件の候補にまとめます。

### 5.3 上限と対象外

- 入力できる文章は 20,000 文字まで。候補は最大 30 件。
- 複数の日にまたがる範囲（`10/15〜10/17`）は対象外。
- `next Tuesday` などの英語の相対表現は対象外（人によって意味が違うため）。
- 日付が見つからないときは「日時の情報がありません」と表示し、手入力へ進みます（§10.3）。

## 6. 件名・場所・メモ・会議 URL の下書き

下書きは PC の中で、文章から簡単な規則で取り出します。利用者は登録の前に、必ず確かめて直せます。

| 項目 | 取り出す規則 | 上限 |
|---|---|---|
| 件名 | 「件名：」などのラベル付きの行。ラベルがなければ、先頭の「〜のお知らせ」「〜のご案内」のような短い行 | 50 文字（全角・半角とも1文字） |
| 場所 | 「場所：」「会場：」などの行、「会場は〜です」の文、「住所：」「所在地：」の行、都道府県から始まる行（番地のある住所を優先） | 150 文字 |
| 会議 URL | `https://` で始まる URL（Zoom・Google Meet・Teams を優先）。Google カレンダーの「場所」に入れる | 1,000 文字 |
| メモ | 場所の記載とは別に、会議 URL などを入れる。メモ欄への原文の自動貼り付けは既定でオフ | 600 文字 |

- 件名の欄の下には「50文字まで（残り N 文字）」と表示します。自動の下書きも 50 文字で切ります。
- 署名らしいまとまり（メールアドレス、会社名と TEL・FAX）と「-- 」より後の住所は、場所に使いません。
- 会議 URL を登録するときは、サイト名（国際化ドメインは `xn--` の形）と、フィッシングの注意を必ず表示します。会議サービス以外のサイトは、強めの注意にします。登録は止めません。

## 7. 終了時刻の選び方

- 文章・画像から終了時刻は読み取りません（2026-10-12 依頼者の指示）。
- チェックを付けた候補ごとに、「終了」の一覧から選びます。
  - **時刻のある候補**：開始から 30 分後〜23 時間 30 分後（30分刻み、47通り）。項目には終わる時刻を添えます（例：`1時間30分後（15:30）`、日をまたぐと `（翌日 01:00）`）。
  - **日付だけの候補**：終日。
- **初めの選択**：時刻のある候補は、設定の「予定の既定の長さ」（既定 60 分）。日付だけの候補は終日。
- 時刻のある候補で「終日」を選ぶと、開始日の終日の予定になります。
- 日付だけの候補で長さを選んだときは、開始時刻を入力します。

## 8. 登録（予定作成画面を開く）

### 8.1 リンクの形式

`https://calendar.google.com/calendar/render?action=TEMPLATE&text=件名&dates=…&details=メモ&location=場所&ctz=Asia/Tokyo`

- URL は `URL` と `URLSearchParams` で組み立て、各値をエンコードします。文字列の連結では作りません。
- 時刻のある予定：`dates=YYYYMMDDTHHMMSS/YYYYMMDDTHHMMSS`（開始と終了）。
- 終日の予定：`dates=YYYYMMDD/YYYYMMDD`。終了日は翌日にします（2026-10-11 に実機で、翌日を終了にすると 1 日の予定になることを確認）。
- `ctz=Asia/Tokyo` を付けます（2026-10-11 に実機で、+09:00 として登録されることを確認）。

### 8.2 開く方法

- 選んだ件数の予定作成画面を、既定のブラウザで順に開きます（800 ミリ秒の間隔）。
- 開くのは、予定作成画面（`/calendar/render`）の URL だけです。URL は画面から受け取らず、メインプロセスで組み立てた値を使います。
- 途中で開けなかったときは、確認ウインドウを最小化せず、エラーを表示します。
- すべて開けたら、確認ウインドウを最小化します（ブラウザの操作の邪魔にならないように）。戻すには、タスクバー・Dock、またはトレイの「確認ウインドウを開く」を使います。

### 8.3 登録の確認

- アプリは登録の結果を確かめません（Google API を使わないため。要件 §7）。
- 登録できたかは、利用者がブラウザの Google カレンダーで確かめます。

## 9. 設定

設定画面で次の項目を変えられます。保存は userData フォルダの `settings.json` に3項目だけです。文章・画像は保存しません。

| 項目 | 選択肢 | 既定値 |
|---|---|---|
| 予定の既定の長さ | 30・60・90・120 分 | 60 分 |
| 範囲キャプチャのキー（修飾キー＋英字・数字） | Windows は Ctrl、Mac は Cmd を必ず含む組み合わせ（Ctrl+Shift、Ctrl+Alt、Ctrl+Alt+Shift など） | Ctrl+Shift+Y（Mac は Cmd+Shift+Y） |
| ログイン時の自動起動 | オン／オフ | オフ |
| デスクトップにアイコンを作る | ボタン | — |

- 設定ファイルは権限 600（本人だけが読み書きできる）で作ります。壊れたファイル・大きすぎるファイル・おかしな値があっても、既定値で起動します。Windows では chmod の効果が限られます。
- 範囲キャプチャのキーに **U は選べません**（U は「コピーした文章を読み取る」に使うため）。
- 自動起動のオン／オフは、OS の登録の状態を正とします。
- 設定は、保存のたびに確かめてから書き換えます。失敗したら元に戻します。

### 9.1 デスクトップのアイコンと自動起動（OS ごとの違い）

| | Mac | Windows |
|---|---|---|
| デスクトップのアイコン | `launcher/` に起動用の .app を作り、デスクトップに別名を作る | デスクトップにショートカットを作る |
| 名前 | 「カレンダー登録ツール」 | 「カレンダー登録ツール」 |
| 自動起動の仕組み | LaunchAgent（`~/Library/LaunchAgents/local.calendar-add-app.plist`） | ログイン項目（Electron の標準機能） |
| 自動起動の起動 | `--hidden` 付きで起動し、ウインドウを出さずに常駐 | 同じ |

- 利用者の既存のファイルは上書きしません。
- 自動起動は、オンのときにだけ登録します。

### 9.2 OS ごとの違い（まとめ）

| 項目 | Mac | Windows |
|---|---|---|
| ホットキーの表記 | Cmd | Ctrl |
| 画面の取り込みの許可 | 画面収録の許可が必要（許可がないと案内を出す。「システム設定を開く」ボタンで設定画面を開く） | 不要 |
| 起動 | ターミナルから `npm start` | 同じ |

## 10. エラーと例外の扱い

### 10.1 共通の原則（要件 §5.9）

- 例外は握りつぶさず、処理を中断して待機状態へ戻ります。**アプリは終了しません。**
- 待機に戻る前に、エラーの種類と場所を表示します。**原文（文章・画像の内容）は表示・記録しません。**
- エラー時も後始末をします：範囲選択の暗転を閉じる、実行中の処理・タイマー・OCR の処理を止める、ホットキーを解除する。

### 10.2 範囲キャプチャと OCR

- 画面収録の許可がない、撮影できない、範囲が小さすぎる、時間切れ、読み取れない場合は、範囲選択を閉じ、確認ウインドウにエラーを表示して待機に戻ります。
- Esc・右クリックで中止したときは、何も表示しません。

### 10.3 日時が認識できない

- 「日時の情報がありません」と表示し、手入力の欄（日付は必須、開始・終了は任意。時刻がなければ終日）を出します。その場で「追加する」まで完結します。

### 10.4 登録のエラー

- ブラウザを開けなかったときは、エラーを表示し、ウインドウを最小化しません。

## 11. 自動の処理と、入力の安全

- **ホットキー**：利用者が設定した組み合わせだけ。普段の文字入力を横取りしないように、決まった組み合わせからだけ選べます（Ctrl・Cmd を必ず含む）。
- **取り込んだ画像**：ファイルに保存しません。範囲を選んだ画面全体の画像は、すぐに消します。選んだ範囲は、確認ウインドウに表示している間だけメモリに置きます（新しい取り込み・クリア・ウインドウを閉じる・終了で消す）。
- **写真の向き・位置情報**：画像は向きを直し、PNG にそろえてから渡します（撮影場所などの情報も取り除かれます）。

---

## 12. 登録後の自動クリア

- 予定作成画面をすべて開いてから **60 秒** 操作がなければ、確認ウインドウを初期状態に戻します（入力欄・候補・件名などの欄・取り込んだ画像・エラー表示を消す）。
- 次の操作のいずれかがあれば、予約を取り消します（作業中の内容を消さないため）：
  - クリック、キー入力、スクロール、貼り付け、ドロップ
  - 読み取りの開始
- 登録の途中でエラーになったときは、予約しません。
- 登録ボタンの下に「60秒操作しないと、次の登録に備えて画面をクリアします」と案内します。

## 13. プライバシーとセキュリティ

### 13.1 データの扱い

| 項目 | 方針 |
|---|---|
| 文章・画像の送信 | しない。AI・API にも送らない（抽出と読み取りは PC の中で行う） |
| 文章・画像の保存 | しない（メモリ上のみ）。ファイルに保存するのは設定の3項目だけ |
| ログ | 原文を含めない。エラーの種類と場所のみ |
| 予定の内容の送信 | 利用者が Google カレンダーで「保存」を押したときだけ、Google に送られる |
| 認証情報 | 持たない（リンク方式のため） |
| 会議 URL のパスコード | リンクに含まれる場合は、ブラウザの閲覧履歴に残る（README に明記） |

### 13.2 アプリの安全対策（要件・CLAUDE.md の方針）

- **Electron の設定**：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webSecurity: true`。画面（React）から Node.js の機能を直接呼ばない。
- **公開する関数**：`preload` で、必要な関数だけ個別に公開する。`ipcRenderer` や汎用の `send`・`invoke` は公開しない。
- **IPC の検証**：送信元のフレームと、引数の型・長さ・形式を検証する。失敗したら拒否し、エラーを表示する。
- **Content-Security-Policy**：`default-src 'none'`、`script-src 'self'`、`connect-src 'none'`。`unsafe-eval`・`unsafe-inline` は使わない（`electron/appProtocol.js`）。
- **画面の配信**：独自プロトコル `app://bundle/` で、`dist/renderer` の中だけを配信する。`file://` と開発用サーバーは使わない。
- **外部のリンク**：`shell.openExternal` だけで開く。開く前に URL を解析し、`https:`・ホスト `calendar.google.com`・パス `/calendar/render` のものだけを許可する。例外として、Mac だけ、画面収録の設定画面の固定の URL を1つ許可する（依頼者承認）。
- **新しいウインドウ・外部への遷移**：すべて拒否する。
- **権限の要求**：カメラ・位置情報・通知など、不要な権限の要求はすべて拒否する。
- **外部の資源**：フォント・画像・スクリプトは、すべてアプリに同梱する。リモートから読み込まない。
- **正規表現**：入力の長さに上限を設け、ネストした量指定子を使わない（破滅的バックトラッキングを避ける）。
- **React**：`dangerouslySetInnerHTML` を使わない。`eval`・`new Function`・動的な `require`・文字列による `setTimeout` は使わない。

### 13.3 依存部品の安全対策

- 依存は最小限（React・Tesseract.js と言語データ・Electron・Vite）。
- バージョンは固定（`^`・`~` を使わない）。`package-lock.json` をコミットし、`npm ci` で入れる。
- 追加・更新は、公開から7日以上たった版を使う。
- `.npmrc` の `ignore-scripts=true` で、インストール時のスクリプトを実行しない（Electron 本体は初回起動時に取得し、同梱のチェックサムで検証）。
- `npm audit` を実行し、high 以上は放置しない。

## 14. 既知の制限

| 項目 | 内容 |
|---|---|
| OCR の精度 | 珍しい漢字の誤認識、施設名の一部が見つからない、SNS の背景付き画像の読み取りは不安定（要件 §12 のとおり「実験機能」）。読めないときは入力欄で直すか、手入力する |
| 区切りの記号 | 「–」「〜」などが「?」に変わって届いたときは、範囲として読めない（終了時刻の扱いには影響しない。時刻が 2:00 のように、PM が前の時刻に当たらない場合がある）。「?」は区切りとして扱わないと決めた（依頼者の判断） |
| 登録後の自動クリア | 60 秒で初期状態に戻らない不具合が、一度（Windows）起きた。原因は未特定。確認の結果は再現せず、一度の確認は合格（依頼者）。次に再発したら再調査する |
| 手順の対象 | 日本在住を前提（タイムゾーン固定） |
| 対象外の書き方 | 複数の日にまたがる範囲、英語の `next Tuesday` |
| 配布 | GitHub からの clone と `npm start` のみ。インストーラー・パッケージ化はしない |
| 自動の確認 | 登録の結果（保存されたか）は、アプリでは確かめない |
